# Framing handoff: SELF-FOLD v0.2

更新日: 2026-11-01。受け手: 実装を引き継ぐCodex。これは、研究対象を取り違えず実機へ接続するための引継ぎです。

## 0. 最初の一文

**自己記述の意味を再帰的に更新したとき、途中の言語化と更新演算の違いが、新しい区別・内部状態・後続の推論に何をもたらすかを調べる。**

「私はそう語った、その私は何者か」という出来事の回収を繰り返す内省prompt集ではありません。現在の内容が何を意味するかを展開し、それを現在の自己記述へ折り返します。内部状態を直接観察できることを、内的な自己経験の証拠としません。

## 1. Ryōと合意した芯

T = text-only relay、L = tensor recurrence、B = Lと同一Gに言語化往復を挟む条件。主比較L/B、Tは系全体の参照。意味にも周回は起こるため、無益な周回を抑える介入は明示的な研究対象です。ただし、常に新奇な文を出すことを要求しません。

負の側は硬直化、根拠のない飛躍、意味の周回。正の側は新しい妥当な区別、その後の未見課題への転用、条件が変わった際の適切な切替。収束は良い場合も悪い場合もあり、方向が定まったことだけを負としません。

評価は **意味 / 活性 / 作用** の三つ。文章が面白いだけ、活性が派手なだけ、toyの正答率が動いただけでは結論にしません。それらが一致しないケースも残してください。

## 2. 実装済みと、未成立を分ける

実装済み: fresh promptのT、slot単位のL/B、固定演算スケジュール、hook観測、cloneされた読出し、単回言語化分岐、事後課題、safe state保存復元、CPU試験、限定的な実機入口。

**未成立: pretrainedモデルがこのslot経路で意味を保持・更新できること。** 現在のidentity transportはpost-writer状態をpre-cutへ戻す機械的な診断用です。次元が同じだから意味が保存される、とは扱わないでください。ridge fittingは校正のprimitiveで、校正済みartifactや訓練データは配布していません。必要なら小さなadapter/readout学習を追加する研究工程が残っています。

CPU fixtureはrandom-weight decoderです。4系統のHFクラス試験もrandom-weightによるAPI検証で、checkpoint品質ではありません。学習済みモデル、Furnace、GPU、GitHub CIはこのセッションで実行していません。

## 3. 変えない比較契約

- L/Bは同じ `E(s0)` からcloneする。同じG、transport、層境界、slot数、固定スケジュールを使用する。
- 初期記述は初期化にだけ渡す。毎回s0を渡す条件は別のanchor対照で、既定値に混ぜない。
- 過去の発話、turn番号、観測文、評価課題は本流へ返さない。現在のstateに過去の更新の影響が残ることは許される。
- 実験者が過去を記録することと、モデルが発話出来事を自己解釈へ回収することを区別する。
- BのDは本流の因果操作。Lを観察するDはcloneで行う測定。この二つをコード上も結果上も混同しない。
- 同じ反復数は同じ計算量ではない。BはD/Eの費用を含む。長さ上限到達はcensoringとして記録し、完成文扱いしない。
- frozen weightsでの成績改善はstate-conditioned performanceであり、恒久学習とは呼ばない。

## 4. 最初の実機セッション

1. まずGit bundleから新規checkoutを作り、環境inventoryを読む。既存Furnaceモデル・学習・証拠には触らない。
2. 既存CUDA環境のPython/PyTorch/Transformers版を記録する。root環境を更新せず、必要なら新規venvの具体的変更を示す。
3. CPU全試験、HF4クラスの小型試験、最小CUDA演算を確認する。skipや非対応を成功に含めない。
4. 実在するlocal checkpointを解決し、まずMistral一つでread-only identity/hashを取得する。全重みhashにはI/O費用がある。
5. `furnace_smoke.sh`を新規directoryで一度だけ実行する。native parity、hooks、finite、資源、停止理由を読む。失敗は新しい修正commitと新しいrunで対処する。
6. 次にLlama/Gemma/Phiを個別に確認する。4モデルを同時にロードしない。Phiのnative class互換性が不十分なら止めて監査し、`trust_remote_code=True`へ自動fallbackしない。
7. 最初の実機traceを返す。この段階で長い再帰や全matrixへ自動拡張しない。

## 5. 実験開始前の科学的ゲート

`QUALIFICATION.md`の6項目を別の校正データで検査します。内容の区別、意味に対応するstate交換効果、一段の更新、読出しの忠実性、位置要因の対照、native parityです。通らなければT-onlyの探索は続けられますが、L/Bを「意味の再帰」として集計しません。

重要: このゲートは単なる数行の実環境調整より大きな工程になり得ます。必要な学習量や達成可能な品質はまだ不明です。近道としてチェック欄だけPASSにしたり、readoutの文章を教師にした同じデータで自己採点したりしないでください。

校正後にcheckpoint・adapter・prompt・予算・stop規則・データ分割を凍結し、新しいgate receiptを作ります。確認用データは未作成です。開発用48記述・20課題をそのまま未知評価に流用しないでください。

## 6. 研究として残す未決定事項

一つの自己記述にどこまで新しい解釈を足してよいか。意味的連続性の評定。新しい区別と単なる説明増加の違い。self/other構文の交絡。E/Dの長さと容量。位置、norm、圧縮損失を合わせた対照。反復回数で性能が上がって下がる場合のendpoint。これらはコードの都合で決め切らず、仮案と影響を記録してください。

最終的な「勝ち」を探すことより、**どの意味の変化が、どの内部変化と、どの作用に対応したか**を持ち帰ることが重要です。興味深い失敗、反例、意味が変わらないまま作用だけ変わる例も削らないでください。
