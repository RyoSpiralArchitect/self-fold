# Correction to write10's artifact description

The first four lines of the archived
[write10 NOTICE](../provenance/message_boundary_20261106/write10/NOTICE.txt)
were copied from write9. Its statements that this study fits pointer readers
and that reference retention is engineered describe **write9**, not write10.
This correction supersedes those descriptive statements for write10.

In write10, the Gemma model and report readers are frozen. The study generates
448 fresh instruction/actual-output reports, reuses archived native scores,
and trains two- and 34-parameter reference-memory cells from downstream
judgment reward across three seeds. The initial reference extraction and
role routing remain supplied; the tested reference retention is learned.
The combined reporting gate fails, as recorded in the
[study results](../provenance/message_boundary_20261106/write10/RESULTS.md).

The original NOTICE and its checksum are retained because write11 explicitly
pins those bytes as a historical input. No result, input manifest, artifact
checksum, license or Gemma term has been silently replaced. The original
implementation remains under Apache-2.0; the accompanying conditions for
Gemma-derived artifacts remain in effect. This is a descriptive provenance
correction, not a change in permissions or experimental evidence.
