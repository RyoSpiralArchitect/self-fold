# 学習されたメッセージ境界を通した自己言及の効果：開発実験仕様（案）

**状態：`DESIGN_ONLY_NOT_EXECUTED`。実行マニフェストの凍結前。レビュー用ドラフト。**

この文書は、preprint v1 の open question――「中間状態を言語に出すこと（T／B 経路）が後の利用を変えるか」――に、1 bit 実験（role_memory）と G stage 診断（PR #28）の知見を組み合わせて挑むための設計案である。既存の結果・gate・preprint v1 は変更しない。資格試験 24 群は読み込み・生成・照合・採点のいずれにも使わない。対象の基点は PR #28 マージ後の main とし、実行前に commit を固定する。

## 1. 元の疑問を、この設計が答えられる形に言い換える

元の問い：同じ中間状態から、言語に出して続ける経路と、状態のまま続ける経路で、後の判断は変わるか。

1 bit 実験が示したのは、「現在の行動表が同一でも、次の更新に必要な区別（役割）が残ることがある」という現象だった。そこで自己言及の問いを次に絞る。

> **更新後の状態が持つ「次に必要な区別」のうち、言語化（D）と再符号化（E(D)）を通っても残るのはどの部分か。残らない部分は、離散メッセージとして学習させると回復するか。**

G stage 診断は、structured 経路で E(D(G)) が hard action ID と二択回答を保存し、float rows と A/B scores を保存しないことを既に示した。つまり言語化が「記号的な中身」を通し「連続的な形」を落とすことは分かっている。未解決なのは、その落ちた部分が機能的に必要か、そして必要なら別の運び方で補えるかである。

## 2. 1 bit 実験から引き継ぐ設計上の教訓

| 知見 | この設計への反映 |
| --- | --- |
| 報酬だけの学習器が「off/off が切替行動を選ぶか」という座標を自力で発見した | メッセージの意味を教師で与えず、凍結 reader 経由の結果報酬だけで学習させる。供給コード天井を別アームに置く |
| 供給された interface（行比較・truth mask・コピー演算）が信用割当を自明にした | 同じプリミティブ群を供給し、学習可能性ではなく「何が書かれるか」を問う |
| 選択した 36 文字列が偶数 parity で易しく、登録ゲートを落とした | 評価文字列は選択せず全列挙し、prefix parity で層別報告する。事後の全数 follow-up を最初から主計画に入れる |
| 2 bit では六履歴を区別できず、3 bit で可能になった | メッセージ幅 m を掃引し、容量限界と学習限界を分ける |
| 教師ありと報酬学習で差が 0 だった | 両アームを同一初期値・同一乱数で比較し、「報酬だけで約束の座標に収束するか」を測る |

## 3. 経路の定義：同じ更新後状態の三通りの引き渡し

対象は structured 経路の四行表 G に、書き込み可能な m bit の離散メッセージを添えたものである。writer は現行と同じく trigger の真理マスクと行比較 feature を受け取り、更新済み表とともに m bit を境界へ書く。次の updater／reader は表とメッセージだけを受け取り、元の文・前の命令・問いを受け取らない。

同じ更新後状態から、引き渡し物だけを変えた三経路を並列に比較する。

| 経路 | 次の段に渡るもの | 対応する元の腕 |
| --- | --- | --- |
| M·slot | 完全な soft 表 + m bit の生値 | L に相当 |
| M·verb | renderer が出した本文のみを parse した表（bit を含めて言語化し、parse で復元を試みる） | T／B に相当する言語迂回 |
| M·verb+sym | 言語化→parse で復元した表 + 記号のまま保存した m bit | 言語化が落とすものと落とさないものの切り分け |

M·verb は言語化後に読み手側で再構成する。parse 不能な行は `UNENCODABLE`／`PARSE_FAIL` として落とさず記録する。三経路は同じ G 出力・同じ次段 updater・同じ reader・同じ問いを共有し、差は境界を越える表現だけとする。structured の外部 world address と embedding bank は経路の構成要素として残る。

## 4. 学習と評価

- writer（m bit を出す小さなパラメータ群）だけを学習する。reader、renderer、表の updater、source compiler は学習しない。
- アーム：(a) 報酬学習メッセージ、(b) 役割教師ありメッセージ、(c) メッセージなし対照（bit は書くが境界で破棄）、(d) 供給コード天井（人が定めた役割符号化）。同一初期値・同一乱数・同一更新回数。
- 訓練は二段以上の編集列に対する凍結 reader の native 正答報酬のみを使う REINFORCE。既存の 512 updates × 128 episodes を基準予算とし、マニフェストで凍結する。
- 評価文字列は事前に全列挙し、prefix parity（off/off での役割交換回数の偶奇）で層化して報告する。一部の容易な文字列を選ばない。
- メッセージの解読：各 bit と候補意味 feature（off/off が切替を選ぶか、veto の有無、役割の置換、前回演算名）との相互情報／決定木読み出しを記録する。「報酬学習が供給コードの座標に収束したか」を主結果の一つとする。
- 主な対照：現在の行動表が同一で次に必要な答えが反対となる履歴対（opposed-history pair）を両側正答かつ A/B margin 反転で採点。修復と破壊の両方、全分母、tie・非ラベル・parse 失敗を status として併記する。

## 5. どの結果が何を意味するか

| 観測 | 許される結論 |
| --- | --- |
| M·slot 正・M·verb 誤・M·verb+sym 正 | 言語化が落としたのは表の連続情報で、離散メッセージは言語を通さなくても運べる。必要な残余は記号化可能 |
| M·slot 正・M·verb+sym 誤 | 必要な残余は m bit にも入らず、表の soft 構造に依存する。言語化の損失は記号化では補えない |
| M·verb 正（sym なし） | 必要な区別は本文として言語化できる形で書かれていた。自己言及による損失はこの課題では検出されない |
| メッセージなし正・学習メッセージ正 | 供給 interface 上で残余情報が学習可能だった。どの座標が選ばれたかを解読結果で報告 |
| 全経路誤・供給コード天井も誤 | carrier より前（更新または reader）に失敗がある。メッセージの意味に帰属しない |

## 6. 先行条件と範囲外

- native（8 slot raw）経路は今回の対象外。PR #28 の S／N／C が reader と carrier を分離するまでは、native で「意味がない」と「読めない」を区別できないためである。正の対照が読めない場合は診断仕様 §7 に従い、explicit action table を E で符号化した状態だけから診断用 reader を学習する別計画を先に立てる。
- 本計画の実行には凍結済み native row reader・renderer・updater の binding が必要であり、モデル checkpoint と tokenizer の SHA256 をマニフェストに含める。CPU だけで完結する部分（履歴列挙・ledger・採点器）は先に実装・テスト可能である。
- 成功しても主張は「この structured 課題・この reader で、言語化が落とす残余を離散メッセージで補えた」までに留め、独立資格試験の開封や preprint への追加には進まない。
