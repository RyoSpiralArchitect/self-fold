# SELF-FOLD

[English](README.md) · 日本語

**モデルの内部状態をいったん言葉にし、その言葉を読み直すと、何が残るのか。** SELF-FOLDでは、重みを固定した言語モデルが短い自己記述を更新する過程を追います。次の更新に渡すのは、その時点の文章か、決まった数の潜在スロットだけです。過去の発話は実験者側に記録します。

| 条件 | 次のステップに渡すもの |
| --- | --- |
| T・文章 | モデルが新しく書いた自己記述。 |
| L・潜在状態 | 内部で1回更新した8個のスロット `G(Z)`。 |
| B・言語化往復 | Lと同じ更新を行い、その結果を文章にしてもう一度符号化したスロット `E(D(G(Z)))`。 |

LとBは同じ初期状態、更新演算、層の境界、生成の停止規則を使います。この特定の言語化往復で何が変わり、その変化が後の課題にどう響くかを調べています。[論文PDF](paper/self-fold.pdf) · [ブラウザで読む](paper/main.md) · [実験プロトコル](docs/PROTOCOL.md)

## 実験

- **最初の符号化・読み出しの学習。** Gemma-2-2B本体を固定し、73,728パラメータの小さな符号化部品を64回更新しました。開発用文章の予測損失は4.31から1.86に下がりましたが、内容識別の正答率は約50%のままでした。対立する記述の状態に入れ替えても、損失の改善はほぼ残りました。学習前の2モデル×2経路も内容の基準に届いていません。[条件・失敗・学習済み部品・生の結果](provenance/carriers_20261102/RESULTS.md)
- **選択肢を読んだ後の、どの位置が効くか。** 新しい6題では、2番目に表示した選択肢の直後にあるピリオド1個の中間層状態を移すと、後続位置をすべて移したときのスコア差の22%（Mistral）・27%（Gemma）が現れました。ドナー側だけ選択肢の順を逆にすると、差の向きも反転しました。一方、そのピリオドだけを外しても差は88%・89%残りました。ここで比べているのは、2つの語句を入れ替えたときのラベルの対数確率差です。[位置別の移植・除去、選択肢を隠した対照、生スコア](provenance/downstream_span_20261101/RESULTS.md)
- **質問を変えれば元の記述の違いを取り出せるか。** Mistral-7B-Instruct-v0.3とGemma-2-2B-ITは、6組の好みを文章で渡すと、ともに24件すべてを識別しました。ところが、1回更新したスロットは各モデルで24種類あったのに、そこから生成された文はモデルごとに1種類でした。その文を再符号化すると、12組すべてで、対になる記述のスコアが同点になりました。[方法・対照条件・生スコア](provenance/slot_content_20261101/RESULTS.md)
- **どの位置の状態を移すと、元の回答を再現できるか。** 状態を取り出す側と戻す側の入力長を揃え、中間層の8スロットだけを移すと、正しく識別できたのはMistralが12件中6件、Gemmaが7件でした。質問をすでに読んだ後続位置の状態を移すと、元の回答が両モデルとも12件すべてで再現されました。Mistralの元の誤答1件も含みます。[入力長と移植位置の対照](provenance/slot_content_20261101/REPLAY_PLAN.md) · [実験結果](provenance/slot_content_20261101/RESULTS.md)
- **Bが同じ状態に戻るのは、生成文が短いためか。** Mistral-7B-Instruct-v0.3で、対になる2つの初期記述を2回ずつ更新しました。EOSを待つ条件では全18生成が自然に終了しましたが、Bはどちらの記述からも同じ13トークンの文を返しました。Bの更新後の状態は停止規則ごとに1種類、Lはそれぞれ4種類でした。[条件・生成例・状態ハッシュ](provenance/mistral_eos_20261101/RESULTS.md)
- **CPUでの動作確認。** ランダム重みの小型デコーダーで4試行を行い、初期状態の一致、保存と復元、計算量、T/L/Bの更新経路を確認しました。[CPU実験の記録](provenance/launch_cpu_20261101/RESULTS.md)

## 再現手順

リポジトリをクローンし、Python 3.11以降で以下を実行します。

~~~bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev,hf]'
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 python -m pytest -q
bash scripts/run_smoke.sh runs/tiny-001
~~~

試行ごとに新しい出力先を指定します。実験記録にはソースコミット、モデルの識別情報、採点前の生スコア、生成の停止理由を残しています。[学習済みモデルでの再現とファイルの照合](docs/REPRODUCING.md) · [モデルと状態の実装](docs/ARCHITECTURE.md) · [意味を検証する基準](docs/QUALIFICATION.md)

[意味ゲートまでの研究計画](docs/SEMANTIC_GATE_PLAN.ja.md)では、質問に依存しない状態の検証、E/Dなどの学習、独立した通過挑戦までを6課題にまとめています。各課題に、肯定的な完了条件と、未達の範囲を記録して次へ進める条件を置いています。最初の符号化・読み出しの学習を終え、内容の保存とGの学習は引き続き未達・保留として残しています。
