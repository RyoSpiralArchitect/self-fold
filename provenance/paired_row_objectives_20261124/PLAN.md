# 4行の状態保存と既定行動の反転を別々に学習できるか

**事前登録案・学習前。** 2026年11月23日の [PR #42 の固定結果](../paired_writer_20261123/RESULTS.md) から設計した追試。今回実施したのは保存済み出力の再集計、入力・バッチ順の照合、CPUでの損失と評価コードの検査まで。次回の主要仮説は、行の正解を明示的に重み付けし、同時に反対donorの行分布を近づけると、平均役割損失の対照よりも正しい役割反転と4行の保存を両立できる、というもの。対象は役割ビットが明示された構造化状態に限る。

[機械可読の全再集計](archive_audit.json) と [標準ライブラリだけで動く集計コード](../../scripts/audit_paired_writer_rows.py)。freshとpreviousの各5経路を別々に収録した。`row_by_donor` は座標ごとに既定行動0・1の順、`row_by_display_position` は表示位置0起算。`donor_relations` は各行を正答一致・誤答一致・異なる実値・片側欠損・両側欠損に分ける。欠損同士を一致に含めない。`role_status` は正方向の反転、逆向きの取り違え、同一、その他の異なる値、欠損を区別する。`rotation_histogram` の添字0〜4は、各条件を満たした表示順の数。分母は常に24表。`--details` で両側の値・正解・後続正答数・表単位の記録までたどれる。

## 4条件と勾配をかける場所

1対は同じメニュー・割り当て・表示順で既定行動の異なる2件。学習時は正しい先行行をteacher forceし、既存のtokenizerで各行動名の最初に異なるトークンのlogitを採る。donorごとの絶対トークン位置は個別に引き、意味座標と選択肢の順を揃える。評価時は各donorが単独で5行を自由生成する。

共通項 B は、元の全文・EOSのtoken CE、5欄それぞれの二択CEの平均、5欄目の正解側符号付きmarginに対する softplus(2 − margin) の両donor・全対平均の和。元の対照にも4行の教師信号が含まれる。追加項 S は両donorの先頭4欄の正解行動への二択CEの平均。追加項 J は同じ意味座標の二つの予測分布間のJensen–Shannon divergence。各分布は二択softmax、温度1、自然対数、混合比1/2。4座標・対で平均し、両donorに逆伝播する。

| 条件 | 目的関数 | 検証する差 |
|---|---|---|
| `mean` | B | PR #42の平均損失を同じ条件で再実行 |
| `row_ce` | B + S | 4行の正解への追加重み |
| `agreement` | B + J | 反対donor間の行分布の一致 |
| `combined` | B + S + J | 追加教師と一致の併用 |

追加項の係数はいずれも1に固定し、探索しない。既定欄には追加項を適用しない。両donorが同じ誤った行動を確信するとJは0になる。Sはその場合も正解側への勾配を返す。自由生成ではメニュー外の語や欠損も起こりうるため、二択分布の一致だけで保存を判定しない。

## 次回の固定手順

- 親adapter、G1、G2、語彙、parser、prompt、role bit、質問を見ないwriterと全語彙の最終読者をPR #42に固定する。G1/G2の共有重み、RoleMemoryの実装、状態変換とparserの実装は、パネル再作成前に既存マニフェストのハッシュで照合する。元のdesign・訓練/評価prompt・親adapter・既存のnative score bankも照合する。最終読者の固定出力は評価時だけ使用する。
- 各条件とも同じ初期adapter（245,760個の学習可能パラメータ）から開始。8メニュー×8割り当て（1対3または3対1）×2 donor×4順の512件。各バッチは4対。AdamW、学習率0.00015、weight decay 0、勾配クリップ1、4周、256 updates、最終点のみ採点する。事前指定したバッチ順seedは257・258・259。同じseed内は4条件で順序を完全共有。257は旧対照の全256バッチと照合する。この設計が測るseed差はバッチ順による差で、初期adapterは共通である。
- 全12 fitの重みとハッシュを閉じてから評価を開始。PR #42と同じ決定論的な順序、8件バッチ、greedy生成、EOSまたは160トークン。親writerは同じスケジュールで評価する。停止条件・生テキスト・トークン・prompt hash、学習ごとのバッチ番号列と損失各項、重み、経路ごとの評価値を別ディレクトリに保存する。途中の失敗や打ち切りを成功として除外しない。全arm・全seedの記録が揃わない場合は主要判定を保留する。
- 評価は各4メニュー×6通りの2対2割り当て×4表示順×2donor。主要パネルはPR #42の `fresh`、副次は `previous`。どちらも再利用であり、次回の結果は既に観察したパネルでの開発上の比較として扱う。2対2の表は今回のfitから除外する。同じ表の両donor・4順を一単位として分割する。独立資格試験は開封・採点しない。
- 各donorの同じ自由報告を14編集×4 world×2順の計112判断に使う。正答には既存の全語彙首位・厳密な符号条件の両方を適用する。対の全要件は両側の4行正解、両側の正しい既定名、両側の全112判断正解の積。欠損や不完全な報告も分母に残す。

## 主要判定と反証条件

主要比較は各seedの `combined` 対 `mean`。以下を**同じseedで同時に**満たし、3 seedのすべてが通った場合に「追試の基準を満たした」とする。これらは事前に選ぶ有限パネル上の判定基準で、有意差検定ではない。

| 指標 | freshでの基準 |
|---|---|
| 評価経路 | direct state・exact reportの全要件が各92/96以上 |
| 行の保存 | 候補の4行正解が164/192以上、かつ同時評価した親からの低下が9件以内 |
| 両立 | 候補が対照より全要件で5/96組以上増え、4メニュー中3以上で純増 |
| 役割と後続判断 | 正しい既定名反転の組数、後続全正解の組数がそれぞれ対照以上 |
| 一致の退化 | 少なくとも1行で同じ誤答を出す組数が対照以下 |
| 順序に対する安定性 | 全4順で全要件を満たす物理的割り当て数が対照以上 |

副次比較は教師のみ対対照、一致のみ対対照、併用対教師のみ、併用対一致のみ。主要比較が通っただけではJ独自の寄与は決まらない。各差分は同じmenu・pattern・rotationで回復と喪失を報告する。誤答一致が増えて後続判断だけが改善した場合、役割反転が落ちた場合、特定表示順でしか成立しない場合を個別に表示する。96提示を独立96表とみなす推論や、同じ24表をseed間で足し合わせた分母による推論は行わない。

## 再現コマンド

リポジトリ直下で実行する。最初のコマンドはPython標準ライブラリのみ、残りはリポジトリのCPU用依存を使う。

```sh
python scripts/audit_paired_writer_rows.py
python scripts/audit_paired_writer_rows.py --details > /tmp/paired-row-details.json
export PYTHONPATH=src CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
python scripts/fit_paired_row_objectives.py --check
python -m pytest -q tests/test_paired_row_objectives.py tests/test_paired_role_writer.py tests/test_structured_report.py
```

将来の実験入口は [runner](../../scripts/fit_paired_row_objectives.py) の `--run NEW_DIR --checkpoint LOCAL_GEMMA --seal FULL_COMMIT`。実行時には確定した事前登録のclean checkout、元と同一のGemma実行環境、リポジトリ外の新規出力先を使う。各seedの結果は集計CLIの `--next PATH/TO/SEED/outcomes.json` で再集計できる。[損失実装](../../src/selffold/paired_row_objectives.py)・[決定論的テスト](../../tests/test_paired_row_objectives.py)。
